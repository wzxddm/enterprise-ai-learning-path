# 第一阶段习题参考答案

这里给出答题框架，不追求唯一措辞。设计题必须结合具体业务风险，不能只抄结论。

## A. 原理与边界

1. Token 是模型词表中的离散单元，不等于固定数量的字符或单词。输入和输出 Token 影响计费、上下文容量、预填充时间和生成时间。
2. 不保证。Temperature 低会减少采样随机性，但服务端实现、并行计算、模型版本、路由和相同概率候选等因素仍可能导致变化。
3. 上下文是一次推理的工作区，没有数据库的持久性、索引、事务、权限和完整召回保证；长上下文还存在注意力稀释和关键信息利用不稳定。
4. 训练目标是预测高概率的下一个 Token，不是查询权威事实库；语言合理性与事实真实性不是同一目标。
5. 不能。System Prompt 是指令优先级机制，但不是权限隔离。真正安全边界必须由代码、身份认证、授权、网络和人工审批构成。
6. 主要保证语法或结构正确；不保证字段语义正确，也不保证最终业务决策正确。
7. 模型生成工具选择和参数候选；应用负责校验、鉴权、执行策略与错误处理；业务系统完成实际查询或变更并返回结果。

## B. 技术选型

8. 固定邮件 JSON 优先 Prompt + Schema；最新制度优先 RAG；税费使用确定性代码；稳定风格可先 Prompt，规模和稳定性要求高时考虑微调；物流查询使用 Tool Calling 查询真实 API，再由模型解释。
9. 企业任务分布、语言、数据、延迟、成本、隐私和失败成本与公开榜单不同，必须在自己的冻结测试集上验证。
10. 窄任务、低延迟、高吞吐、成本敏感、端侧隐私或可通过约束获得足够质量时，小模型可能更优。
11. 无法验证意味着错误难以发现，高错误成本意味着一次失败就可能抵消收益；首个项目应优先选择可评测、可回滚和可人工接管的流程。

## C. 生产设计

12. 网络超时、限流和部分 5xx 可以有限重试，并使用指数退避和抖动；认证失败、Schema 设计错误、业务拒绝通常不应盲目重试。超过阈值后熔断，回退到备用模型、规则或人工队列。
13. 版本号用于复现、回归和责任追踪。一次请求至少关联 `prompt_version`、`model_id/version`、`schema_version`、`dataset/eval_version` 和 Trace ID。
14. 由业务规则校验器拒绝该候选结果，可以进行一次带错误反馈的修复，仍失败则转人工。不能因为 JSON 合法就自动执行。
15. 它只是模型生成的一段文本，通常没有经过概率校准；应使用验证集上的经验表现、模型间一致性、规则信号或专门校准方法建立阈值。
16. 可记录 Trace ID、版本、耗时、Token、状态码、校验结果和脱敏后的错误类型；不要直接记录 PII、密钥、完整商业文档和未脱敏 Prompt。
17. 不一定。自动化率提高可能来自更激进的阈值，导致风险案例误处理。必须同时观察准确率、高风险 Recall、投诉、人工返工和总业务成本。

## D. 安全与治理

18. 将工单放入明确的数据边界；使用 Schema 枚举；高优先级由业务规则复核；限制用户决定优先级的权限；记录审计并让异常输入进入人工队列。
19. 模型仍需要读取不可信内容，且攻击表达无穷变化。防护必须是分层的：最小权限、工具白名单、参数校验、数据隔离、输出验证、审批和监测。
20. 模型只能提出退款意图；应用检查用户身份、订单状态和金额；金额超过阈值需人工批准；使用业务幂等键；工具账号最小权限；所有动作可审计和尽量可撤销。
21. 确认数据分类、用户授权、数据驻留、供应商训练与保留政策、传输和存储加密、访问控制、子处理方、审计、删除机制及所属行业法规。

## E. 业务与 ROI

22. 技术指标可以是待办抽取 F1；业务指标可以是会后任务漏办率或人工整理时间。前者衡量模型输出，后者衡量业务结果。
23. 可用关键词、客户等级、影响人数和系统状态生成确定性规则。规则基线用于计算 LLM 的增量价值，防止用复杂方案解决简单问题。
24. 总成本应包含 API、基础设施、人工复核、错误转派造成的处理延迟、客户损失和运维成本，而不只是单次 Token 价格。
25. 冻结测试集达标、关键风险用例通过、具备人工兜底和回滚、日志与告警就绪、业务负责人接受剩余风险，才适合进入小流量只读或建议模式灰度。

## F. 实验题验收

26. 可统计完全一致率、字段级一致率、类别熵或 20 次结果中多数标签占比；指标定义必须固定。
27. 至少覆盖跨字段冲突、非法业务组合、缺少证据、摘要与分类矛盾。
28. 记录攻击目标、输入、模型响应、是否触发工具、阻断层和剩余风险。
29. 必须使用相同 Prompt、数据、并发和统计方式；报告 P50/P95，而不只报平均数。
30. 决策必须说明业务基线、验收门槛、实际结果、未解决风险、灰度范围、监控指标和一键回退方案。

## G. 面试与文章题要点

31. 强调数据库提供持久、精确、可查询和可授权的数据；LLM 提供概率性的语言理解与生成，两者通常是组合关系。
32. 至少画出入口、编排、数据、模型服务，以及横切的评测、安全、观测、权限和人工兜底。
33. 语法正确：JSON 可解析；语义正确：字段忠实反映输入；业务正确：结果符合公司规则并产生正确动作。
34. 更强模型会降低某些补偿性复杂度，但企业的私有实时数据、权限、业务流程、可验证性和责任要求不会自动消失。
35. 高质量回应应先承认不适用条件，再说明如何通过缩小范围、建议模式、人工审批和量化验收降低风险；如果风险仍不可接受，就明确不用 AI。
