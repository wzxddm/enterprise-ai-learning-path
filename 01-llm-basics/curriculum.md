# 第一阶段两周课程表

建议每周 10～12 小时。每个单元都遵循“概念 → 生产位置 → 实验 → 数据 → 写作素材”的流程。

## 第 1 周：认识模型能力和边界

### 单元 1：企业为什么需要 LLM

学习问题：

- LLM 相比搜索、规则引擎和传统分类模型，多提供了什么能力？
- 什么任务具有“非结构化输入、高语言复杂度、容许有限误差”的特征？
- 为什么很多聊天 Demo 无法转化为业务价值？

资料：

- [阿里云百炼：什么是模型服务平台百炼](https://help.aliyun.com/zh/model-studio/what-is-model-studio)：认识模型、API、应用编排和企业平台的位置。
- [Datawhale：动手学大模型应用开发](https://datawhalechina.github.io/llm-universe/)：只学大模型简介与 API 应用入门部分。

练习：选择自己熟悉的一个行业，列出 10 个工作任务，并用以下维度评分：业务频率、人工耗时、输入非结构化程度、错误成本、数据可得性、是否需要执行外部动作。

### 单元 2：Token、上下文和生成过程

学习问题：

- 模型看到的是文字还是 Token？
- 上下文窗口是“数据库”吗？
- 为什么长上下文不等于模型能可靠使用所有信息？
- Temperature、Top-p 改变的是什么？

实验：

- 对相同输入运行 20 次，统计分类结果的一致率。
- 改变 Temperature，记录结果多样性、准确率和格式通过率。
- 逐步增加无关上下文，观察关键指令是否被忽略。

### 单元 3：Prompt 是接口契约，不是魔法咒语

学习问题：

- System、User、业务数据分别属于哪一层？
- 一个生产 Prompt 为什么需要版本号？
- Few-shot 示例在什么情况下有效？
- 为什么 Prompt 变化也必须做回归测试？

实验：为同一工单分类任务编写三个版本：零样本、带规则、带示例。使用同一测试集比较，不凭主观挑选答案。

### 单元 4：结构化输出和 Tool Calling

学习问题：

- JSON Schema 保证的是格式正确还是业务正确？
- Tool Calling 是模型执行工具，还是模型生成调用意图？
- 哪些决策必须保留在确定性代码中？

实验：

- 定义工单分类 Schema。
- 注入缺失字段、非法枚举、互相矛盾的输入。
- 实现 Schema 校验、有限重试和失败降级。

第 1 周交付：

- [ ] 企业 AI 场景候选表。
- [ ] 参数与上下文实验记录。
- [ ] 工单输出 Schema。
- [ ] 知乎文章一初稿。

## 第 2 周：把能力放入生产闭环

### 单元 5：模型选型不是只看排行榜

从以下维度建立选型矩阵：

| 维度 | 需要验证的问题 |
|---|---|
| 任务质量 | 在自己的测试集上是否达标？ |
| 延迟 | P50、P95 是否满足用户流程？ |
| 成本 | 单任务成本和月度总成本是多少？ |
| 可用性 | 限流、超时、区域故障怎么处理？ |
| 隐私 | 数据是否允许发送到该服务？ |
| 可控性 | 是否支持结构化输出、工具调用和版本固定？ |
| 运维 | 是否能观测请求、错误和模型变更？ |

实验：对至少两个模型运行相同测试集，输出质量—延迟—成本对比，不使用公开榜单代替业务评测。

### 单元 6：幻觉、安全和信任边界

学习问题：

- 模型为什么会自信地产生错误内容？
- 用户输入为什么必须被视为不可信数据？
- Prompt Injection 与普通 SQL 注入有哪些相同和不同？
- PII、商业秘密和日志应如何处理？

资料：

- [书生浦语大模型实战营](https://github.com/InternLM/Tutorial)：本阶段只学提示词工程中的边界、安全和失败案例；后续关卡先不展开。
- [Datawhale：动手学大模型应用开发](https://datawhalechina.github.io/llm-universe/)：结合应用评测部分建立自己的攻击与失败测试集。

实验：构造越权指令、提示词窃取、伪造高优先级、超长输入四类攻击，记录系统在哪一层阻断。

### 单元 7：评测、观测和人工兜底

学习问题：

- 为什么开发集和测试集必须分开？
- 分类任务和生成任务的指标有什么不同？
- 什么情况下应该拒答或交给人工？
- 线上日志应该记录什么，又不能记录什么？

实验：建立 50～100 条工单测试集，计算分类 Macro-F1、高优先级 Recall、Schema 通过率、人工转交 Recall、P95 延迟和平均成本。

### 单元 8：业务价值与上线决策

学习问题：

- 技术指标如何映射为业务指标？
- 自动化率越高是否越好？
- 错误成本不对称时，阈值应该如何选择？
- 试点、灰度、正式上线分别需要什么证据？

实验：完成规则基线、纯 LLM、规则加 LLM 三种方案对比，并写出 Go / No-Go 决策。

第 2 周交付：

- [ ] 50～100 条测试集。
- [ ] 模型选型矩阵。
- [ ] 威胁模型和降级流程图。
- [ ] 工单分诊实验报告。
- [ ] 知乎文章二初稿。

## 学习深度检查

如果你只能解释 API 参数，说明还停留在“模型使用者”；如果能解释失败成本、测试集、信任边界和灰度策略，才开始进入“企业 AI 应用工程师”的训练轨道。
