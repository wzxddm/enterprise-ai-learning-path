# 阶段一：从“会调用模型”到“理解企业 AI 产品”

时间：第 1～2 周核心学习，可增加 1 周完成文章打磨

这一阶段不追求掌握所有 API，而是建立一个贯穿后续学习的判断框架：企业为什么要使用 LLM、它位于生产系统的什么位置、哪些问题适合它、哪些问题不适合，以及如何证明它产生了业务价值。

## 阶段产出

1. 一张企业 LLM 应用技术地图。
2. 一个可评测的“客服工单分诊助手”。
3. 一份不少于 50 条的测试集和实验报告。
4. 两篇知乎专栏文章，而不是零散学习笔记。
5. 一次阶段答辩：能够从业务、技术、风险和 ROI 四个维度解释方案。

## 必须掌握的概念

- Token、Tokenizer、上下文窗口和上下文工程。
- System / User Prompt、结构化输出、Tool Calling。
- Temperature、Top-p 和非确定性。
- 幻觉、知识截止、Prompt Injection、数据泄露。
- 预训练、SFT、RAG、Agent、微调的职责边界。
- 模型选型中的质量、延迟、成本、隐私和可用性。
- 企业生产闭环：业务指标、评测、观测、降级、人工兜底。

## 第一阶段的核心判断

```text
LLM 不是业务系统本身，而是一个有概率出错的能力组件。

生产应用 = 模型
         + 业务上下文
         + 确定性代码
         + 数据与权限
         + 评测与观测
         + 人工兜底
```

## 阶段完成标准

- [ ] 不把“模型回答看起来不错”当作上线依据。
- [ ] 能说出某个场景的业务基线、目标指标和失败成本。
- [ ] 能区分语法正确、语义正确和业务正确。
- [ ] 能画出一次请求的数据流、信任边界和降级路径。
- [ ] 工单项目达到预先设定的离线验收门槛。
- [ ] 发布或完成两篇符合专栏规范的长文草稿。
