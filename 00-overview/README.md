# 总览与学习方法

## 最终目标

20 周结束时，应当能够：

- 解释 Transformer 和 Decoder-only LLM 的核心工作原理。
- 独立设计包含检索、引用和评测的 RAG 系统。
- 设计具有工具调用、状态管理和安全边界的 Agent。
- 判断 Prompt、RAG、微调分别适合什么问题。
- 使用 LoRA 完成一次小模型微调。
- 建立固定评测集并进行回归测试。
- 部署开源模型，分析延迟、吞吐量和显存占用。

## 每周时间安排

以每周 10 小时为例：

| 活动 | 时间 | 说明 |
|---|---:|---|
| 视频或教材 | 3 小时 | 建立概念和原理框架 |
| 阅读代码与文档 | 2 小时 | 以官方文档和优秀实现为主 |
| 编码实验 | 4 小时 | 每周必须产生可运行代码 |
| 复盘记录 | 1 小时 | 记录结论、问题和下一步 |

## 学习原则

每学一个概念，至少回答四个问题：

1. 它解决什么问题？
2. 最小实现是什么？
3. 常见失败场景是什么？
4. 如何通过数据证明它有效？

每个阶段采用相同流程：

```text
视频建立直觉 → 书籍补全原理 → 官方文档动手 → 项目验证 → 复盘输出
```

## 三个进阶方向

完成共同路线后，再决定长期方向：

| 方向 | 重点内容 | 推荐后续资料 |
|---|---|---|
| LLM 应用工程 | 高质量 RAG、Agent、评测、可观测性 | Full Stack Deep Learning、AI Engineering |
| 大模型算法 | 预训练、数据治理、对齐、论文复现 | Stanford CS224N、CS336 |
| AI 基础设施 | CUDA、分布式训练、推理优化 | vLLM、DeepSpeed、Megatron-LM |

## 阶段验收规则

- 不以“视频看完了”作为完成标准。
- 必须提交可运行代码或实验记录。
- 必须写出失败案例和结论。
- 无法用自己的话解释核心原理时，暂不进入下一阶段。
